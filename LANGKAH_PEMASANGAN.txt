AMAN AJA — PAKET PERBAIKAN BRANKAS, MENU PEMILIK & MANAJEMEN ANGGOTA

BACA DULU
Paket ini memperbaiki menu pemilik, folder per kategori seperti File Explorer, dan pesan error upload. Paket ini tidak bisa menjamin sistem online berhasil sebelum konfigurasi Firebase, Cloudinary, dan Vercel milik Anda benar serta diuji. Jangan masukkan KTP/KK asli sebelum seluruh tes berhasil.

1. GITHUB
- Buka repository basku9411/LEMARI-KANGBASE.
- Ekstrak ZIP ini.
- Upload ISI ZIP ke ROOT repository (bukan ZIP-nya). Izinkan file lama ditimpa.
- Pastikan folder api/, lib/, src/ dan file package.json, index.html, vite.config.js, firestore.rules ikut terunggah.
- Jangan hapus repository.
- Jangan upload .env.local, file service-account Firebase, API Secret Cloudinary, atau private key.

2. FIRESTORE RULES
- Firebase Console > Firestore Database > Rules.
- Ganti rules dengan isi file firestore.rules dari paket ini, lalu Publish.
- Rules ini memakai UID pemilik yang sudah diketahui pada proyek AMAN AJA. Pastikan UID tersebut sama dengan VITE_ADMIN_UID dan ADMIN_UID di Vercel.
- Jangan tempel firestore.rules ke menu Firebase Storage Rules. Aplikasi ini menyimpan file di Cloudinary, bukan Firebase Storage.

Jangan hapus variabel yang sudah benar. Periksa nama dan nilainya di Project > Settings > Environment Variables.

4. DEPLOY ULANG
- Setelah GitHub selesai menerima perubahan, buka Vercel > Project AMAN AJA > Deployments.
- Tunggu deployment terbaru selesai dan berstatus Ready.
- Jika build gagal, jangan lanjut tes upload. Buka deployment tersebut dan baca Build Logs.
- Jika Anda mengubah Environment Variables, lakukan Redeploy agar nilai baru dipakai.

5. UJI DENGAN FILE DUMMY
A. Masuk memakai akun pemilik yang UID-nya tercantum di atas. Pastikan menu Foto & Gambar dapat dibuka dan Brankas Pemilik tampil.
B. Buat folder uji di Foto & Gambar, buka folder tersebut, buat subfolder, lalu upload satu foto dummy. Pastikan foto berada di folder yang dibuka.
C. Pindah ke Video. Pastikan folder Foto tadi tidak muncul di kategori Video.
D. Kembali ke Foto, buka folder dan uji buka/download/hapus file dummy.
E. Buka menu Anggota. Pastikan semua akun terdaftar tampil dengan statusnya: Aktif, Nonaktif, Menunggu persetujuan, atau Ditolak.
F. Daftarkan akun uji kedua. Pastikan akun itu Menunggu persetujuan dan tidak dapat membuka brankas sebelum disetujui.
G. Dari menu Anggota, aktifkan akun uji. Pastikan status menjadi Aktif, lalu uji upload file.
H. Nonaktifkan akun uji dari menu Anggota. Pastikan akun tersebut tidak dapat masuk kembali/mengakses API dan file tetap tersimpan.
I. Aktifkan kembali akun yang sama. Pastikan akses kembali normal dan file lama tetap ada.
J. Masuk dengan akun uji lain. Pastikan tidak bisa melihat file akun pertama. Ini tes wajib sebelum menyimpan dokumen pribadi.

6. PENGATURAN ANGGOTA
- Saat pendaftaran baru, anggota mengisi nama lengkap. Daftar pemilik menampilkan nama dan email; akun lama yang belum memiliki nama tetap ditampilkan memakai email.
- Menu Anggota hanya muncul untuk UID pemilik yang cocok di VITE_ADMIN_UID.
- Endpoint /api/member-status juga memeriksa ADMIN_UID dan Firebase Admin SDK di server; mengganti tampilan browser saja tidak memberi hak pemilik.
- Menonaktifkan anggota mengubah status Firestore menjadi disabled, menonaktifkan akun Firebase Authentication, dan mencabut token refresh.
- Mengaktifkan anggota mengembalikan akun menjadi approved. Menolak pendaftaran mengubah status menjadi rejected.
- File Cloudinary dan dokumen metadata tidak dihapus saat anggota dinonaktifkan.

7. JIKA UPLOAD GAGAL
- Baca pesan lengkap yang tampil di aplikasi.
- Buka Vercel > Project > Deployments > deployment terbaru > Functions/Runtime Logs.
- Cari fungsi /api/cloudinary-signature pada waktu upload.
- Salin hanya teks error-nya jika perlu bantuan. Jangan kirim API Secret, token login, private key, atau isi FIREBASE_SERVICE_ACCOUNT_JSON.

CATATAN PENTING
- Build penuh lokal belum dapat diverifikasi karena npm install timeout saat paket sedang diunduh. Vercel harus menunjukkan deployment Ready sebelum aplikasi dipakai.
- Cloudinary paket gratis memiliki batas pemakaian/kuota; tidak ada jaminan penyimpanan tanpa batas.
- Pembayaran otomatis Xendit belum aktif. Pembayaran masih diverifikasi manual.
- Folder lama tanpa kategori tetap terlihat di Semua File. Folder baru akan mengikuti kategori tempat folder dibuat.
- Jangan gunakan data sensitif sampai semua tes dummy dan tes pemisahan antar-akun berhasil.
